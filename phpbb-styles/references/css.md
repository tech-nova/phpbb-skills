# CSS

## The entry point

`styles/prosilver/theme/stylesheet.css` is nothing but an ordered list of
imports. Verbatim from 3.3.17:

```css
@import url("normalize.css?hash=48eb3f89");
@import url("base.css?hash=7c5543be");
@import url("utilities.css?hash=d8f72c42");
@import url("common.css?hash=843d5d5f");
@import url("links.css?hash=18286e16");
@import url("content.css?hash=d6d1338b");
@import url("buttons.css?hash=56f0d25f");
@import url("cp.css?hash=50d868ab");
@import url("forms.css?hash=9016b55c");
@import url("icons.css?hash=64da33ce");
@import url("colours.css?hash=fcb2f289");
@import url("responsive.css?hash=c9d32cba");
```

**The order is the cascade.** `colours.css` comes second-to-last on purpose:
every colour in prosilver is set there, so a re-skin can be one file.
`responsive.css` comes last so its media queries win.

| File | Holds |
|---|---|
| `normalize.css` | cross-browser reset |
| `base.css` | element defaults: html, body, headings, tables |
| `utilities.css` | small helper classes |
| `common.css` | layout: wrapper, header, footer, navigation, panels |
| `links.css` | every anchor state |
| `content.css` | posts, topic lists, forum lists, profiles — the bulk |
| `buttons.css` | button and icon-button styling |
| `cp.css` | control panels: UCP, MCP |
| `forms.css` | inputs, selects, fieldsets, validation |
| `icons.css` | the icon font and its classes |
| `colours.css` | **all colour values** |
| `responsive.css` | media queries |

## The files not in that list

Three theme files load separately, from templates rather than from
`stylesheet.css`:

| File | Loaded by |
|---|---|
| `bidi.css` | `overall_header.html:53` and `simple_header.html:31`, inside an RTL condition |
| `tweaks.css` | `overall_header.html:65` and `simple_header.html:35`, inside a browser condition |
| `print.css` | `viewtopic_print.html:10` and `ucp_pm_viewmessage_print.html:10` |

They use `{T_THEME_PATH}` and `?assets_version={T_ASSETS_VERSION}` directly:

```html
<link href="{T_THEME_PATH}/bidi.css?assets_version={T_ASSETS_VERSION}" rel="stylesheet">
```

If you fork one of these, remember it is the template that references it, not
`stylesheet.css`.

## Cache busting

Two mechanisms:

- `?hash=…` on the `@import` lines — regenerated by phpBB when the theme is
  refreshed from the ACP.
- `?assets_version={T_ASSETS_VERSION}` on template-loaded assets — driven by
  `config['assets_version']`, which the ACP increments.

**Neither updates by itself when you edit a file by hand.** Purge the cache
(`cache:purge`), and bump `assets_version` from the ACP if browsers keep serving
the old file.

## Inheritance and overriding

A child style inherits every `theme/` file it does not ship. The child's
`stylesheet.css` is loaded **after** the parent's, so the usual pattern is:

1. Ship your own `stylesheet.css` that imports the prosilver files you keep,
   then your own file last.
2. Put your overrides in that last file.

Editing a copy of `content.css` is the maintenance-heavy alternative: at each
phpBB release you must diff your copy against the new prosilver one. Adding a
file avoids that entirely.

For a re-skin with no layout change, overriding `colours.css` alone is often
enough — that is what it is separated for.

## Responsive

`responsive.css` uses max-width breakpoints, in this order (verified by reading
its `@media` blocks):

| Query | Line |
|---|---|
| `max-width: 320px` | 4 |
| `max-width: 350px` | 12 |
| `max-width: 430px` | 18 |
| `max-width: 500px` | 28 |
| `max-width: 550px` | 95 |
| `max-width: 700px` | 109 |
| `min-width: 701px` | 547 |
| `min-width: 701px` and `max-width: 950px` | 557 |

`700px` / `701px` is the main phone-to-desktop boundary. The narrower queries
are progressive refinements, not a separate system; the two `min-width` blocks
at the end restore desktop-only behaviour.

Because `responsive.css` is imported **last**, a rule you add in an earlier file
will be overridden inside those breakpoints. Add your responsive rules after
the import, or in your own trailing stylesheet.

## RTL

`bidi.css` holds the right-to-left overrides and is loaded conditionally from
the header templates, based on the language's direction. It flips floats,
margins, paddings, text alignment and borders.

A style that adds layout rules must add their mirror to its own bidi file, or
RTL languages break. Test with an RTL language pack installed rather than
assuming.

## Icons

prosilver 3.3 uses an icon font, configured in `icons.css`. Font files live in
`assets/`. Adding an icon means adding to the font, not dropping in an image —
check `icons.css` for the existing class naming before inventing one.
